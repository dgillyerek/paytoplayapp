# DEV-001 — Core merge loop

Status: **in repo** (domain + headless tests + Unity wiring).

## Goal

Ship a playable **7×5** board whose only verb is **drag-merge**, with rules in data, not in UI code.

## Rules

| Input | Result |
| --- | --- |
| Drop on empty cell | Move |
| Drop on same piece, combined count &lt; 3 | Stack (still same tier) |
| Drop on same piece, combined count = 3 | Consume 3, spawn **1** next-tier piece (`MergeRecipe`) |
| Drop on different piece / no recipe / OOB / empty source | **Snap-back** — board unchanged |

Recipes live in `MergeCatalog` / `GroveCatalog.CreateDefault()`. Adding a tier is a catalog edit, not a loop edit.

## Code

- `MergeSession.TryDrag` — single entry for the loop
- `DragResult.Applied` vs `DragResult.SnapBack`
- `DragMergeController` — pointer drag, ghost follow, snap-back lerp, merge punch
- `BoardView` — greybox 7×5 cells + colored piece quads
- Tests: `tests/Grove.Domain.Tests/MergeLoopTests.cs`, `SnapBackTests.cs`, `BoardGridTests.cs`

## Out of scope for DEV-001

Progression meta, real IAP, live ops, juice beyond snap-back, 3D art.
